# CooPay 官方插件源

本仓库直接提供 CooPay 插件协议 v2 的 Lua ZIP 包，无需 GitHub Releases。

## 在 CooPay 中使用

新版 API 已预置此官方源。在「插件中心 → 插件源」刷新官方源，再到「市场」安装插件；新安装的插件需手动启用。已有部署请更新 API 后使用。

- 源 ID：`official`
- 类型：`github`
- 仓库：`LanQin996/CooPay-Plugins`
- 分支：`main`
- 子目录：留空
- 索引：[index.json](index.json)

不要求使用者提供公钥或私钥，不提供 `index.sig`。管理员信任插件源即授权执行其中的插件；客户端仍校验 HTTPS、文件大小、SHA-256、包结构及 manifest。渠道业务所需的支付宝/微信密钥与验签不受此规则影响。

所有包要求宿主插件协议 v2。微信支付插件使用微信 API v3；插件协议版本与渠道 API 版本不同。debug 插件仅供本地调试。ZIP 为跨平台 Lua 包，运行时由 API 启动隔离子进程。

支付宝支付 3.0.4 的旧版 CooPay 地图兼容从电脑网站支付页面提取原生 `qrCode`，标准 v2 仍返回结构化表单。手机网站产品保留 H5 表单能力；支付宝手机网站页可能不含原生二维码，故不声明 QR 启动类型。网站二维码重定向只允许 manifest 中列明的支付宝 HTTPS 主机。

微信 API V2 插件支持普通商户 Native 扫码收款、查单、支付通知及 API 全额退款。收款仍只填 APPID、商户号、商户 API V2 密钥；商户 API 证书和私钥为选填，申请退款时必需。缺证书的退款预检不预留资金；已受理退款查询无需证书。旧订单可在同商户基础凭据未变时临时补齐缺失证书，不改历史记录。APPID 必须绑定商户并具备 Native 权限。请先更新 API（通用 mTLS/AES、退款预检及回调支持），再升级插件至1.1.0。V2 与 V3 使用独立 ID，可同时安装。

## 发布维护

支付宝身份验证需企业账号签约对应场景；实名配置经 CooPay 现有实名 Vault 加密保护。首版为 RSA2 公钥模式，不包含外部 H5 唤端包装或小程序 SDK，须先迁移宿主至 **0071** 并更新 API/前端，再安装配置。

索引与所引用的 ZIP 必须在同一提交发布，目录序号递增。CooPay 下载会将 `main` 固定到提交 SHA，避免混用文件。包路径、大小和 SHA-256 以索引为准。更新只检查，不自动安装。

在 CooPay-Go 源码仓库运行 `go run ./cmd/plugin-market-publish -source-id official -out-dir <本仓库目录>`，测试与校验全部成功后检查差异并自行提交推送。发布工具不自动执行 Git 操作，不把渠道凭据或任何私钥提交到本仓库。

支付宝支付 3.0.5 修复通知 URL 的宿主 orderNo 路由提示被误计入 RSA2 验签的问题。该提示须匹配通知内已签名的 out_trade_no；重复参数及其他未签名字段仍拒绝。升级当前插件代码即可处理历史通知 URL，不需重新付款。

支付宝支付 3.0.6 补齐真实通知处理：支付宝可能把 notify_url 的 orderNo 从 URL 转移到 POST 表单，3.0.5 仅排除 URL 提示仍会验签失败。现在先严格合并并拒绝重复参数，再移除唯一宿主提示并检查它等于已签名的 out_trade_no；其他字段完整验签。已通过真实支付宝签名通知原文重放及重复通知幂等验证。

微信支付 API v3 3.0.1 增加本地配置校验的安全诊断：缺失字段、APIv3 密钥长度、商户 RSA 私钥和微信支付公钥解析分别返回固定错误类别。诊断不记录任何凭据值，不会请求微信网关；不替代商户权限/APPID绑定验证。

微信支付 API v3 3.0.2/3.0.3 增加商户私钥安全诊断：能够区分误填商户证书、加密私钥、非 RSA、RSA 位数不支持及无法识别/损坏的 PEM/DER。诊断只返回固定类别和必要的位数元数据，不回显或记录密钥内容；不请求微信网关。

微信支付 API v3 3.0.4 修复渠道表单单行密码框粘贴 PEM 时换行被浏览器移除的问题：插件在内存中恢复 PEM 行格式；不记录或回显密钥。另会明确拒绝把证书 PEM 当作微信支付公钥 PEM。
